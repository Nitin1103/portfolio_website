# Build My Personal Portfolio Website

You are an expert **product designer, UX designer, frontend engineer, interaction designer, and creative developer**.

Your task is to design and build a **beautiful, modern, premium personal portfolio website** for me.

Do not create a generic developer portfolio template. The website should feel like a carefully designed personal brand for a serious software engineer who works across **software engineering, cloud, backend systems, and AI/GenAI**.

The final result should be something I would be proud to send to recruiters, hiring managers, engineers, and potential employers.

---

# 1. PRIMARY OBJECTIVE

Build a portfolio that communicates three things within the first 10 seconds:

1. **I am a capable software engineer.**
2. **I build real things rather than just listing technologies.**
3. **I am actively interested in modern cloud, AI, and software engineering.**

The website should feel:

* Modern
* Premium
* Minimal
* Technical
* Intelligent
* Confident
* Human
* Visually memorable
* Fast
* Responsive
* Professional

Avoid making it feel:

* Corporate
* Generic
* Like a resume pasted onto a webpage
* Like a template from a portfolio generator
* Excessively flashy
* Full of meaningless animations
* Like a graphic designer portfolio
* Like an AI-generated website

The design should have personality without sacrificing usability.

---

# 2. IMPORTANT DESIGN PRINCIPLE

Do NOT start coding immediately.

First think through the entire website as a product.

Before implementation:

1. Determine the information architecture.
2. Determine the visual hierarchy.
3. Determine the typography system.
4. Determine the color system.
5. Determine the component system.
6. Determine the interaction/animation strategy.
7. Determine the responsive behavior.
8. Determine how projects will be presented.
9. Determine what should be above the fold.
10. Then implement it.

You are allowed to make reasonable design decisions yourself, but they should support the goals above.

---

# 3. TECH STACK

Use a modern production-quality frontend stack.

Preferred:

* Next.js
* TypeScript
* React
* Tailwind CSS
* Modern CSS where appropriate
* Lucide icons or another clean icon library
* Framer Motion / Motion for meaningful animations

Use the latest stable versions available in the development environment.

Do not introduce unnecessary dependencies.

Keep the architecture clean and maintainable.

The website should be easy for me to modify later.

---

# 4. OVERALL VISUAL DIRECTION

Create a **premium dark-first developer portfolio**.

Think:

* Linear
* Vercel
* Raycast
* Stripe
* modern AI startups
* high-end engineering portfolios

But DO NOT copy any of them.

Take inspiration from the qualities of these products:

* excellent typography
* restrained color usage
* strong spacing
* subtle borders
* beautiful hover states
* excellent micro-interactions
* visual hierarchy
* sophisticated motion

The site should feel like:

> "A really good engineer made this."

rather than:

> "A designer made a flashy website to show off."

---

# 5. COLOR SYSTEM

Use a dark background as the primary theme.

Suggested direction:

* Near-black / charcoal background
* Off-white primary text
* Muted gray secondary text
* One distinctive accent color

Do not use a rainbow of colors.

Use the accent color sparingly for:

* links
* active navigation
* important highlights
* small gradients
* interactive states
* status indicators

Avoid huge neon gradients everywhere.

The design should remain sophisticated.

Implement a subtle light-mode option if it can be done cleanly without compromising the primary design.

---

# 6. TYPOGRAPHY

Typography is extremely important.

Use a modern sans-serif such as:

* Geist
* Inter
* Satoshi
* Manrope

Prefer Geist if available.

Use strong typography hierarchy.

The hero heading should be large but not absurdly oversized.

Use:

* large display typography for the name/headline
* medium-weight section headings
* highly readable body text
* muted typography for metadata

Do not use excessive font weights.

Pay particular attention to:

* line height
* letter spacing
* paragraph width
* whitespace

The site should feel spacious.

---

Create a minimal sticky navigation.

Desktop:

Left:

Right:

* About
* Experience
* Projects
* Skills
* Contact

Also include:

* GitHub icon/link

* remain unobtrusive
* have a subtle translucent/blurred background when scrolling
* indicate the active section
* smoothly scroll to sections

Mobile:

Use a clean hamburger/menu interaction.

Do not create a giant complicated mobile menu.

---

# 8. HERO SECTION

The hero section is the most important part of the website.

It should immediately communicate who I am.

Use this information:

Name:

> Nitin Sharma

Primary positioning:

> Software Engineer building reliable software, cloud systems, and AI-powered experiences.

Create a strong supporting paragraph along the lines of:

Do not make the copy sound like generic LinkedIn language.

Make it concise and human.

Include two primary CTAs:

> View my work

and

> Get in touch

Also provide subtle GitHub and LinkedIn links.

---

# 9. HERO VISUAL

Do NOT use a generic stock photograph.

Do NOT use a cartoon avatar.

Do NOT create an unnecessary 3D human.

Instead create an abstract technical visual.

Possible direction:

A subtle animated "engineering system" visual consisting of:

* nodes
* connections
* small data flows
* code-like fragments
* subtle grid
* particles
* system architecture aesthetic

Keep it subtle.

The visual should support the content rather than compete with it.

On mobile, simplify or reduce the visual.

Performance is more important than visual complexity.

---

# 10. AVAILABILITY / STATUS ELEMENT

Near the hero, create a subtle status indicator:

> ● Open to opportunities

or

> ● Currently building

Make it visually elegant.

Do not make it look like a giant badge.

---

* building practical software

> Understand the system, not just the framework.

# 12. EXPERIENCE SECTION

* Role

* varying card sizes

* technical diagrams

# 21. ANIMATIONS

Animation is important, but restraint is critical.

Use subtle motion for:

* page load
* hero text entrance
* navigation
* section reveals
* project card hover
* buttons
* links
* background elements

Examples:

* fade + slight upward movement
* subtle scale
* border transitions
* gradient movement
* text reveal

Avoid:

* excessive parallax
* spinning 3D objects
* huge particle systems
* constant motion
* distracting cursor effects
* animations that slow the page

Every animation should have a purpose.

Respect:

`prefers-reduced-motion`

---

# 22. MICRO-INTERACTIONS

Make the site feel polished.

Examples:

Buttons:

* subtle movement on hover
* arrow moves slightly
* border/brightness changes

Project cards:

* image slightly scales
* border becomes more prominent
* metadata subtly changes

Navigation:

* active section indicator

Links:

* elegant underline or color transition

External links:

* small arrow/external-link icon

These details matter.

---

# 23. CUSTOM CURSOR

A custom cursor may be used ONLY if it genuinely improves the design.

Do not use a giant glowing cursor.

If implemented:

* keep it subtle
* disable it on touch devices
* ensure it never interferes with usability

If it feels gimmicky, remove it.

---

# 24. BACKGROUND

Create a sophisticated background.

Possible elements:

* subtle radial gradient
* extremely subtle grid
* noise/grain texture
* faint glow
* technical lines

Keep contrast low.

The background should not look like:

"AI website with purple blobs everywhere."

Avoid overused purple/blue gradient backgrounds.

---

# 25. RESPONSIVE DESIGN

The site must be excellent on:

* large desktop
* laptop
* tablet
* mobile

Do not simply shrink the desktop layout.

Design mobile intentionally.

On mobile:

* simplify navigation
* reduce hero visual complexity
* stack project layouts
* preserve whitespace
* ensure buttons are touch-friendly
* avoid horizontal scrolling
* maintain readable typography

Test at:

* 1440px
* 1280px
* 1024px
* 768px
* 390px
* 375px

---

# 26. ACCESSIBILITY

Follow good accessibility practices.

Ensure:

* semantic HTML
* keyboard navigation
* visible focus states
* sufficient color contrast
* proper heading hierarchy
* alt text for meaningful images
* aria labels where necessary
* reduced-motion support

Do not sacrifice accessibility for aesthetics.

---

# 27. PERFORMANCE

The website should load extremely quickly.

Optimize:

* images
* fonts
* animations
* JavaScript
* component rendering

Avoid unnecessary client-side components.

Use server components where appropriate.

Do not install large libraries just to achieve a small visual effect.

The final website should feel instant.

# 34. INTERACTION PHILOSOPHY

The website should reward exploration.

Subtle discoveries are encouraged.

For example:

* hover states reveal information
* project cards reveal technology
* links have elegant transitions
* sections animate into view
* project visuals have small interactive details

But the user should never have to "figure out how the website works."

Navigation must remain obvious.

---

Prioritize information in this order:

1. Who I am
2. What I build

---

# 36. FINAL DESIGN TEST

After implementation, review the website as if you were a hiring manager seeing it for the first time.

Ask:

* Can I understand what this person does within 5–10 seconds?
* Does the site feel credible?
* Does it look professionally designed?
* Are the projects easy to find?
* Does the portfolio demonstrate engineering ability?
* Is there enough personality?
* Is anything unnecessarily flashy?
* Does anything look obviously AI-generated?
* Does mobile look intentional?
* Would I be comfortable sending this URL to a recruiter?

Iterate until the answer to all of these is yes.

# 38. MOST IMPORTANT INSTRUCTION

Do not optimize for "how impressive can I make the website?"

Optimize for:

> **"How can I make a hiring manager remember this engineer and want to see his work?"**

The website should feel like the digital equivalent of a very strong engineer:

**calm, thoughtful, technically capable, curious, modern, and confident.**

Build the complete website, not just a mockup.

Take ownership of the design decisions.

If you encounter ambiguity, choose the option that produces the most polished and professional result while avoiding fabricated personal information.

Once the first version is complete, perform a visual and UX review yourself and improve anything that looks generic, awkward, inconsistent, or AI-generated.

The final result should look **finished and production-ready**, not like a starter template.
