# Portfolio Development Rules

## General
- Build production-quality code, not a prototype or throwaway demo.
- Prioritize visual quality, usability, accessibility, performance, and maintainability.
- Make thoughtful design decisions independently instead of asking for approval on every small decision.
- Do not fabricate personal information, experience, projects, achievements, certifications, metrics, or links.
- Use clearly marked placeholders whenever information is missing.

## Design
- The portfolio should feel premium, modern, minimal, technical, and distinctive.
- Avoid generic AI-generated aesthetics, excessive gradients, excessive glassmorphism, unnecessary 3D elements, and gimmicky animations.
- Prioritize typography, spacing, composition, hierarchy, and subtle micro-interactions.
- Animations should be purposeful and restrained.
- Maintain a consistent design system across the entire site.
- Design mobile layouts intentionally rather than simply shrinking desktop layouts.

## Code
- Use TypeScript and strongly typed data structures.
- Prefer reusable components and a clean component architecture.
- Keep portfolio content centralized so it can be easily edited later.
- Avoid unnecessary dependencies.
- Avoid duplicated code and massive components.
- Use semantic HTML and accessible components.
- Keep client-side JavaScript to a minimum where possible.
- Do not modify configuration or dependencies unnecessarily.

## Content
- Never invent facts about me.
- Keep placeholder content clearly identifiable.
- Write concise, natural, human-sounding copy.
- Do not use generic buzzwords or exaggerated claims.

## Quality
- After implementing a feature, inspect the result visually.
- Check desktop, tablet, and mobile layouts.
- Check for console errors, broken links, TypeScript errors, layout issues, and accessibility problems.
- Fix problems you discover rather than merely reporting them.
- Before declaring the project complete, perform a full UX and visual polish pass.

## Decision Making
- When requirements are ambiguous, choose the option that best supports a professional software-engineering portfolio.
- Do not add features merely because they are technically impressive.
- Optimize for making the portfolio memorable to recruiters and hiring managers, not for maximizing visual effects.
